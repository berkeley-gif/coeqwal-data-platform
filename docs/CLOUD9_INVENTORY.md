# Cloud9 environment inventory

_Snapshot of the supported production environment. A Linux dev host that wants to mirror it can use this as a reference, but local development is unsupported (see [`scripts/README.md`](../scripts/README.md)). Regenerated by running `scripts/cloud9_snapshot.sh` on Cloud9._

## How to (re)generate

Open Cloud9 (the `coeqwal-db-admin` environment), activate the project venv, then from the repo root:

```bash
bash scripts/cloud9_snapshot.sh --write
```

The script writes its output to this file. Commit the result.

## When to regenerate

- Anyone upgrades Python, rclone, AWS CLI, Docker, or psql on Cloud9.
- The IAM role attached to the Cloud9 EC2 instance changes.
- The repo gains a new module with new dependencies.
- A new developer cannot reproduce the environment on a Linux dev host.

## What this file contains once generated

| Section | What is captured |
|---|---|
| Host | OS, kernel, disk free |
| Python | `python3 --version`, `pip freeze` (when venv is active) |
| rclone | Version, configured remote names |
| AWS | CLI version, caller identity, configured region |
| Docker | Version (if installed) |
| Postgres client | `psql --version`, presence of `DATABASE_URL` / `SUPERUSER_URL` (passwords masked) |
| Git | Version, current branch, HEAD commit |

No secrets are written (passwords in connection strings are masked, only env-var presence is reported).
